# Marco

Find your other phones in a room. You call "Marco", it answers "Polo".

Install Marco on your Android phones and pair each pair of phones once with a QR code. A phone can be paired with several others. When one goes missing, open **Find <name>** on another. You search for one phone at a time and get:

- **Hot/cold** from Bluetooth signal strength: Kalman-filtered RSSI, polled about 4×/s over a GATT connection, with a warmer/colder trend.
- **Proximity beeps** that speed up as you get closer, like a Geiger counter.
- A **Ring** button. The lost phone plays its alarm sound at max volume (gets through silent/vibrate), vibrates, and blinks its flashlight for 30 s.
- **Auto-ring when close**, which rings the lost phone once the signal is strong (default ≥ −70 dBm).

No internet, no account, no Google services.

## Build & install

Requirements: a full JDK 17–25 (with `javac`), the Android SDK (platform 35), and two phones on Android 12+ with BLE. The toolchain is Gradle 9.2.1, AGP 8.13.1 and Kotlin 2.2.21.

1. Open this folder in Android Studio and let Gradle sync, or set `sdk.dir` in `local.properties`.
2. Plug in each phone and press **Run**, or from the command line:
   ```sh
   ./gradlew assembleDebug
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```

## First run (on both phones)

1. Tap **Allow** for Bluetooth (and notifications).
2. On phone A, tap **Show pairing code**. On phone B, tap **Scan pairing code**.
3. Check that the 6-digit **safety code** matches on both, name the other phone, then tap **Pair** on B and **Done** on A.
   To add more phones later, use **Pair another phone → Show code / Scan code** on the home screen.
4. Recommended: **Ring through Do Not Disturb** and **Stay findable in the background** (both are cards on the home screen).
5. Tap **Test ring** to check it's loud enough with the phone on silent.

## Finding a phone

Open **Find &lt;name&gt;** and walk slowly, holding your phone in front of you. Pause for about a second at each spot, because the filter needs a moment to settle. Turn around once in a while: your body can absorb 10 dB or more. When it reads **Hot**, tap **Ring** and follow the sound.

Rough guide for two phones indoors: −50 dBm ≈ within arm's reach, −65 ≈ same room, −80 ≈ next room. It varies a lot by phone model and furniture.

## How it works

```
 lost phone (FindableService)                 finder (FinderEngine)
 ───────────────────────────                 ──────────────────────
 BLE advert, ~1 Hz:                           scan (low latency)
   service data = HMAC(K, window)[0..8]  ───▶   match current/prev/next window ID
   (ID rotates every 15 min)                    connect GATT, priority HIGH
 GATT server                                    readRemoteRssi every 250 ms → Kalman → heat
   nonce  (read)  ── fresh 16 B nonce   ───▶
   cmd    (write) ◀── op ‖ HMAC(K, nonce‖op)[0..16]
 Ringer: alarm stream @ max, vibrate, torch
```

- **K** is a 256-bit key generated by the inviter and passed in the QR code. Each pairing has its own K, and both phones of a pairing store it in app-private storage.
- **One advert per pairing**: a legacy advert only has room for one 8-byte ID, so a phone with N pairings runs N advertisements, each carrying that pairing's rotating ID. The finder matches only the ID of the phone it's looking for. The GATT server accepts a command signed with any paired K.
- **Rotating ID**: strangers can't follow your phone by its advert. Only someone who has K can link the IDs.
- **Single-use nonces**: a sniffed ring command can't be replayed.
- No OS-level Bluetooth bonding is involved. Authentication happens at the application layer, so there are no pairing popups.
- Advert RSSI and connection RSSI can use different TX power, so the filter resets when it switches between them rather than blending them.

## Tuning

All constants are in `finder/FinderEngine.kt` (companion object):

| Constant | Default | Meaning |
|---|---|---|
| `RSSI_FAR` / `RSSI_NEAR` | −95 / −45 dBm | Map to heat 0 → 1 |
| `AUTO_RING_RSSI` | −70 dBm | Auto-ring threshold (8 dB hysteresis before it re-arms) |
| `RSSI_POLL_MS` | 250 | Connection RSSI poll rate |
| `TREND_DB` | 1.5 dB over 2 s | Warmer/colder sensitivity |

Filter noise is set in `RssiFilter` (`processNoisePerSec`, `measurementNoise`). Raise the measurement noise for a smoother but slower reading.

## Known limits / troubleshooting

- **Nothing found while scanning.** The scan permission is declared with `neverForLocation`, and a few OEM builds filter some adverts in that mode. If it's never "Seen", remove `android:usesPermissionFlags="neverForLocation"` from the manifest, add `ACCESS_FINE_LOCATION` to the manifest and to `Perms.RUNTIME`, and turn Location on.
- **The lost phone stopped being findable.** Some OEMs (Xiaomi, Huawei, OnePlus, Samsung "deep sleep") kill foreground services. Grant the battery exemption and lock Marco in recents. See https://dontkillmyapp.com.
- **Do Not Disturb.** The alarm stream already ignores silent mode, and most DND setups allow alarms. With DND access granted, Marco also temporarily switches "Total silence" to "Alarms only". On Android 15+ "modes", the user's own mode can still win.
- The finder thinks the ring lasts the full 30 s even if someone silences it on the lost phone.
- **Many pairings.** Each one uses a Bluetooth advertiser slot on the phone being found. Most phones have at least 4–8 slots. If you run out, the home screen says which paired phones this one isn't findable by.
- The finder only scans with the screen on. That's deliberate: unfiltered scans stop when the screen is off.

## Layout

```
core/      Protocol (UUIDs, HMAC IDs & commands), PeerStore (key + settings, QR format), Perms
findable/  FindableService (advertiser + GATT server), Ringer, BootReceiver
finder/    FinderEngine (scan → connect → RSSI → heat, beeps, auto-ring), GattLink, RssiFilter
ui/        HomeScreen, PairScreens (QR show/scan), FindScreen (+ FinderViewModel)
```
